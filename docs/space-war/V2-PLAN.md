# Space War Battle v2 — 升級規劃

> 目標：**遊戲機制不動**（v1 已完善），把「聲光」大幅拉到電影級；同時把技術底座升級到新版 Three.js + WebGPU，並盡量自動化，讓不寫程式的你也能驗收、回溯、擴充。

## 0. 先講結論

| 問題 | 建議 |

## 1. 現況盤點（為什麼要升級）

- Three.js **r128**（2021 年），所有程式是「全域共用」的傳統腳本，沒有模組；新版 Three.js 已不再提供這種載入方式的後處理模組，所以**必須先做模組化**才能升級。
- 自訂著色器（天空、星點、光束、粒子、火球／煙霧、護盾、電影感後處理、艦體損傷…）全是 `ShaderMaterial`（GLSL）。**WebGPU 渲染器不吃 `ShaderMaterial`**，要改寫成 TSL（Three.js 的新著色語言，同一份程式可轉成 WGSL／GLSL）。
- 效能瓶頸在 CPU 逐顆更新與 GPU 填充率；WebGPU 的 compute shader 可以把粒子／煙霧／碎片整個搬到 GPU。
- 聲音目前是程序合成（numpy/scipy）的單聲道取樣＋簡單殘響，層次與空間感有限。

## 2. 架構（v2）

```
gadget/space-war-battle-v2.html        頁面（importmap 指向 vendor/three）
assets/space-war/v2/
  engine/      渲染器抽象（WebGPU 優先、WebGL2 備援）、後處理、粒子、音訊
  game/        機制（從 v1 的 battle-sim/core 原樣搬移，改成 ES 模組；邏輯不改）
  data/        艦艇／武器資料表（DEF 抽成 JSON，之後調數值不用碰程式）
  vendor/three/ 固定版本的 Three.js r186（含 three/webgpu、three/tsl）
```

重點：**機制層（模擬）與渲染層徹底分離**。v1 已經是「模擬資料 → 渲染」的結構，v2 只換渲染與音訊；日後要做 Godot 版，模擬規則與資料表可直接移植。

## 3. 階段規劃

### 階段 A — 地基（不改畫面，只求一模一樣）
1. 把 Three.js 升到 **r186** 放進 `vendor/`；`importmap` 載入。
2. 把 v1 的 12 個腳本改成 **ES 模組**（機械式轉換）。
3. 先用 **WebGLRenderer**（新版）跑起來，**逐項比對畫面一致**：顏色管理（sRGB/線性）、燈光強度單位、`PlaneBufferGeometry` 等被移除的 API。
4. 自動化：Playwright 截圖基準測試（固定鏡頭 × 20 個場景），每次改動自動比對差異，超過門檻就標紅。
- 驗收：v2 頁面與 v1 肉眼無差異、可玩、效能不低於 v1。

### 階段 B — WebGPU 渲染器 + TSL 重寫
1. 換成 `WebGPURenderer`（自動退回 WebGL2；不支援的瀏覽器照樣能玩）。
2. 把自訂著色器依序改寫成 TSL／NodeMaterial：天空 → 星點 → 光束 → 護盾 → 艦體損傷 → 火球／煙霧 → 後處理。
3. 粒子／火焰／煙霧／碎片改成 **compute shader**（GPU 自己更新，數十萬～百萬顆）。
- 驗收：同樣場景幀數明顯高於階段 A；Firefox／Safari 退回 WebGL2 仍正常。
- 風險：WebGPU 在沙盒的無頭瀏覽器跑不了，**這階段的最終效能需要你在真機回報**（我會準備一鍵回報腳本：頁面上按 F3 顯示 FPS、GPU、解析度、後端，截圖貼給我即可）。

### 階段 D — 音訊大升級
1. **取樣來源**：目前是程序合成。v2 加入真實取樣管線——你可以自己挑 CC0／授權素材（Freesound、Sonniss GDC 免費包、Kenney 等），丟進資料夾即可；我寫好**自動處理腳本**（裁切、響度正規化、轉 Opus/MP3、產生 manifest）。沙盒連不到素材站，所以素材需要你下載後交給我（或放進 repo）。
2. **立體聲＋空間化**：HRTF 3D 定位、距離衰減、都卜勒、聲波延遲（已有誇張聲速）、大艦遮擋時低通。
3. **動態混音**：側鏈壓縮（爆炸時音樂自動壓低）、戰況強度驅動的多層配樂（stems 依強度淡入淡出）、無線電語音加通訊濾波與雜訊。
4. **回響**：多組卷積殘響（太空艙、開闊空間、艦內）。
5. **水下感低頻**：飛彈／護盾已改成深沉風格，v2 統一整套音色風格。
- 驗收：提供「試聽頁」（`gadget/space-war-audio-lab.html`），按鈕逐項試聽，你只要說「這個太吵／太悶」。

## 4. 「正經遊戲引擎」與 MCP

**MCP 是什麼**：讓 AI（我）直接操作外部軟體的連接器，例如直接在 Blender／Godot／Unity 裡建模、擺場景、跑測試。

我查到的現況（多為第三方、非官方，品質不一，需你在 claude.ai 的連接器設定中啟用才能用，我這邊目前沒有任何遊戲引擎類 MCP 已連線）：

| 工具 | MCP | 適合做什麼 | 備註 |
|---|---|---|---|
| **Blender** | 有（BlenderMCP 等） | 建模、材質、烘焙、匯出 GLB | 我現在已經用 `bpy` 無頭模式做同樣的事，**不一定需要 MCP**；MCP 的好處是你能在畫面上即時看到我改的模型 |
| **Godot 4** | 有（多個第三方） | 原生／Steam 版的「正經引擎」 | 免費開源、可匯出網頁（單執行緒）；我最建議的原生版路線 |
| Unity | 有（官方套件需 Unity 6） | — | 網頁輸出龐大、授權複雜，不建議 |
| Unreal 5 | 有（社群／官方插件） | 超高畫質單機 | 學習與硬體門檻最高，不建議 |
| SketchUp | 有（官方） | 簡易建模 | 與本專案關聯低 |

**建議路線**：
1. **現在～半年**：Three.js r186 + WebGPU（v2），網頁直接玩、零安裝、可分享連結。
2. **之後想上 Steam／要更高畫質**：以 Godot 4 做原生版。因為 v2 把「機制」與「資料表」獨立出來，Godot 版可重用資料表與 GLB／音訊素材，只需重寫渲染。
3. MCP：先**不依賴**；你若想看我即時建模，再啟用 Blender MCP。

## 進度（階段 A、B 第一部分已完成）

- **A 完成**：Three.js r186 放入 `assets/space-war/v2/vendor/three/`（含 `three/webgpu`、`three/tsl`、後處理與 GLTF 載入器）；`gadget/space-war-battle-v2.html` 以 importmap 載入；`boot.js` 提供相容層，v1 的模擬與 UI 程式（`v2/legacy/`）幾乎原封不動。以固定亂數種子對 6 個固定場景比對 v1/v2：低畫質平均像素差約 7–20、亮度差 ≤ 3（階段 A 相容層版本）。
- **B 部分完成**：`WebGPURenderer`（自動退回 WebGL2；`?r=gl` 強制退回、`?r=gpu` 強制 WebGPU）；所有自訂 GLSL 著色器改寫成 TSL 節點材質（`v2/engine/nodes.js`）：光束、粒子、火球／煙霧、護盾、莫比烏斯環、衝擊波、星點、太空塵、艦體損傷、面板接縫、鐵墓輪廓光；天空改成「啟動時烘焙成立方體貼圖」；後處理改成 TSL `RenderPipeline`（`v2/engine/post.js`）：泛光 + 1/4 解析度電影感 + 最終合成。WebGPU 與 WebGL2 兩個後端都能完整載入並繪製遊戲（沙盒用軟體 Vulkan 驗證）。
- **尚未做**（下一步）：
  1. 粒子／火球／煙霧／碎片改成 **compute shader**（GPU 自己更新）。目前仍由 CPU 每幀寫入實例資料，只是繪製走 WebGPU。這是效能的最大提升點。
  2. 艦隊實例矩陣改由 GPU 端更新（讓上千艘艦艇的 CPU 負擔降到最低）。
  3. 與 v1 的逐格視覺比對：WebGPU 後端的色彩與亮度還需微調（泛光、天空、護盾）。
  4. 階段 C（視覺大升級）與 D（音訊）。
- **F3 面板**：遊戲中按 F3 顯示後端、FPS、解析度、顯卡、艦艇與粒子數——請在真機截圖回報。

- **一致性**：v2 在 WebGL2 與 WebGPU 兩個後端以同一套程式、固定亂數種子比對 6 個場景，色彩、天空、泛光、艦體光影一致；剩下的亮度差來自兩次執行的戰況不同。
- **HDR 泛光**：泛光改直接吃場景的 HDR 亮度（門檻 1.15 線性亮度），爆炸與光束超過 1.0 的能量會真的暈開，不再被夾在 0~1。
- **劇情分段調色**（僅劇本模式）：出征偏冷青 → 交戰漸暖 → 巨劍降臨前轉紅 → 末日血紅。
- **即時陰影（F10，預設關）**：主光的陰影相機跟著鏡頭前方約 1.5 km（涵蓋 ±3 km），大艦的艦橋／砲塔會在自己艦體上投影；位置吸附格點避免閃爍。
- **艦隊規模（F9，預設 ×2）**：×1~×5，初始艦隊、敵軍波次、增援、戰機都按倍率增加（`?scale=N` 或 F9，記在 localStorage）。實例化容量提高（護衛艦 2500、戰機 2500、敵機 6000…）。

## build 43 — 艦隊不再整片桃紅
- 原因：`boot.js` 包裝的 `PointLight` 建構子會忽略 decay 參數（強制 0），鐵墓的紅色點光（強度 6×π）對整個戰場等強、無距離衰減，艦隊環的艦艇全被染成桃紅。
- 修法：`tombLight` 建構後再設 `decay = 1.4`，強度改 168000，使 1500 單位處與舊版等亮、艦隊環（≈7000）約 1/8；同時側後方粉紅補光 0.55 → 0.3。
- 量測（近景巡洋艦，艦體像素平均 RGB）：舊 (93, 76, 134) → 新 (55, 65, 125)，紅偏消失，呈藍銀色；靠近鐵墓時仍會有紅光。
- 巨劍光源（`doomObj.light`）有同樣的 decay 被忽略問題，但那是終結技演出的整體紅染，刻意保留未動。
- 實機亮度／色調仍需肉眼確認；想再多（或少）一點紅色氛圍，調 `tombLight` 強度或 decay 即可。

## build 44 — 取消護盾、武器打在艦體上、光束命中電焊火花
- **取消能量護盾**：艦艇 `sh/shMax = 0`，原護盾值併入艦體血量（總耐久不變）；不再有護盾吸收、護盾泡泡、「護盾失效」廣播與擊中音。（玩家機的個人護盾條不動。）

## build 45 — 戰艦飛彈：垂直發射、兩段點火、有慣性但敏捷
- 艦載飛彈（`fireShipMissiles`，巡洋艦等）改由艦背沿艦「上方」垂直發射：第一段「冷發射」0.6~0.85 秒，白色燃氣團、減速上升、無火焰；第二段主發動機點火（閃光＋星芒＋火花＋噴煙），急加速到 470 單位/秒並轉向目標。齊射略呈扇形。
