# 中期規劃：換遊戲引擎，把聲光效果大升級

> 狀態：規劃稿（2026-10）。目前線上版是 `gadget/space-war-battle-v2.html`（Three.js r186 + WebGPU，build 21），玩法機制已完整。
> 目標：聲光效果大幅升級；使用者沒有程式經驗，要盡量由 Claude 自動化處理；目標裝置是桌機；艦艇數量要有「史詩感」。

---

## 1. 先講結論

1. **推薦路線：先做 Godot 4 的「驗證小專案」（spike），通過再整個搬。** 不要一開始就整個重寫。
2. **UE5 與 Unity 不推薦當第一選擇**，原因不是它們不好，而是「Claude 在雲端能不能替你寫、跑、測」這個條件：
   - Godot 的專案是**純文字檔**（場景 `.tscn`、腳本 `.gd`／`.cs`），可以用 Git 管理，Claude 能直接寫、改、審查，也能在雲端的無頭模式跑自動化測試。
   - Unity 與 UE5 的核心資產（場景、材質、特效、Blueprint）是**二進位或圖形介面編輯檔**，AI 很難直接改；而且 Unity 編輯器需要授權啟用、UE5 體積巨大，**我在雲端環境沒辦法裝來測試**，只能靠你的電腦手動操作。
3. **同時保留低風險備案：繼續強化現有 Three.js 版。** 先確認「網頁版的天花板在哪裡」，因為你現在的 v2 在高畫質、×5 艦隊規模已經很順，換引擎要贏過的是這個基準。
4. 兩條路不衝突：**Godot 驗證小專案與 Three.js 強化可以交替做**，最後用同一個固定場景比較，由你用眼睛決定。

---

## 2. 你真正要的是什麼？引擎能幫多少？

| 想要的東西 | 現有 Three.js v2 | Godot 4 | Unity / UE5 |
|---|---|---|---|
| 泛光、調色、體積光、景深 | 已有（泛光、體積光、調色） | 內建 Glow、體積霧、調色、SSR／SSAO；Forward+ 渲染器 | 最強（UE5 Lumen／Niagara） |
| 粒子與特效（光束、爆炸、尾焰） | GPU 計算，已做 | GPUParticles3D、拖尾、碰撞；有視覺化編輯器 | Niagara／VFX Graph，**最強** |
| 大量艦艇（數千艘） | 已可 ×5，順暢 | MultiMesh 可以；模擬邏輯要用 C# 才夠快（待實測） | Unity DOTS／UE Mass 最強 |
| 音訊（混音、空間音效、殘響） | Web Audio，簡易 | 音訊匯流排、效果器、3D 音場，夠用；可接 FMOD | Unity／UE 皆可接 FMOD／Wwise，**最專業** |
| 過場動畫（大招演出） | 手寫程式驅動 | AnimationPlayer 時間軸，視覺化 | Sequencer／Timeline，**最強** |
| 非程式員的編輯工具 | 無 | 有編輯器，但要在你電腦上開 | 有，最完整 |
| **在雲端由 Claude 自動寫＋測** | **可以（現況）** | **可以（無頭模式；有條件）** | **不可行／很吃力** |
| 發佈方式 | 網址即玩（GitHub Pages） | 桌機執行檔；網頁版有限制 | 桌機執行檔（UE5 無實用網頁版） |

重點：**畫面品質的最大差距在 UE5，但那條路需要你自己在電腦上做大量手動工作**；Godot 是「進步明顯、又能讓 Claude 自動化」的折衷。

## 3. 規劃的階段與判斷關卡

> 「Session」指我們一次連續的工作對話，大小不一，這裡只用來排先後，不是時間承諾。

### 階段 0：準備（現在到你睡醒後）
- 完成剩下三個模型：仙舟無畏艦、仙舟星槎（玩家機）、黑塔空間站（TRIPO＋Blender MCP，流程已跑通）。
- 整理可跨引擎沿用的素材清單（見第 5 節），確認格式（GLB、MP3、文字表）都在 repo。
- 你決定三件事（第 7 節）：發佈方式、能否接受重寫、視覺目標。

### 階段 1：Godot 驗證小專案（約 2～3 個 session）⭐ 判斷關卡
在 repo 開 `godot/` 資料夾，做一個**只有畫面、沒有玩法**的測試場景：
1. 匯入 6 艘 GLB 模型，看材質與光照效果。
2. 艦隊壓力測試：同時 2,000～5,000 艘，在你的電腦上跑幾 fps。
3. 光束、爆炸、護盾用 GPUParticles3D／著色器做一遍。
4. 泛光、體積霧、調色、鏡頭效果，重現 v2 的畫面。
5. 把鐵墓大招（巨劍與衝擊波）用 AnimationPlayer 重做一遍。

**判斷關卡（你來決定）**：同一個畫面截圖並排比較，並看幀數。
- 明顯更好、而且順暢 → 進階段 2。
- 差不多或更慢 → 停損，把力氣放回 Three.js 強化（階段 B）。

### 階段 2：移植玩法（約 5～8 個 session）
- 資料：艦艇數值表、敵我配置、波次、故事台詞時間軸，直接轉成資料檔。
- 模擬：AI、碰撞、武器、護盾、增援、鎖血；用 **Godot .NET（C#）**，因為模擬規模大，GDScript 恐怕太慢（**需在階段 1 先實測確認**）。
- 介面：選單、HUD、指揮官與飛行員兩種介面、四語言（Godot 的翻譯表）。
- 驗證：沿用 v2 的「固定亂數種子」做法，用同樣的種子比對行為。

### 階段 3：內容與聲光精修（約 3～5 個 session）
- 音訊：你之前說要找真實音效素材，這時建一條正式的混音流程（戰鬥、音樂、台詞三個匯流排，戰鬥音效在大招轉場淡出，音樂不壓低）。
- 特效：光束熔渣、艦體損傷、爆炸連鎖、體積雲、鏡頭光斑。
- 大招演出：舉劍、下刺、衝擊波，改成時間軸動畫。

### 階段 4：打包與發佈（約 1～2 個 session）
- 用 GitHub Actions 自動打包 Windows 執行檔，放到 GitHub Release，你下載就能玩。
- 網頁版：Godot 可以輸出網頁，但有限制（見第 6 節），**不保證與桌機版同等畫質**，視需求決定要不要。

### 階段 B（備案）：強化 Three.js 版
隨時可以插入的低風險改善：
- 更好的後處理（鏡頭光斑、景深、動態模糊）。
- 真實音效取樣的混音流程（取代現在的程式合成音）。
- 用新的 TRIPO 模型做更細緻的材質（法線、發光）。
- 更多特效層次（艦艇尾焰、護盾波紋、環境塵埃）。

## 6. 風險與還不確定的事

1. **Godot 的網頁輸出有限制**：高階渲染器（Forward+）不能用在網頁，網頁版只能用相容渲染器，畫質會打折；而且部分網頁設定需要特殊標頭，GitHub Pages 預設不一定支援。**所以換 Godot 之後，「網址即玩」可能不再是主要發佈方式。**
2. **大量艦艇的模擬效能**：GDScript 可能不夠快，C# 才有機會追上現在的 JavaScript。這是階段 1 要實測的第一件事，我現在不能保證。
3. **雲端測試畫面的能力有限**：雲端沒有真正的顯卡，Godot 的高階渲染可能只能用軟體模擬，截圖與幀數都只能參考；**最終畫質與效能仍然要你在自己的電腦上看**。
4. **Godot 的 MCP 工具成熟度我沒驗證過**：Blender MCP 我們已經實際跑通，但 Godot／Unity 的 MCP 不確定穩定。規劃上**不依賴它**，我們以「寫文字檔＋命令列」為主。
5. **工作量**：這是重寫，不是升級。階段 2 加起來可能是目前所有工作量的好幾倍。所以要有階段 1 的停損點。
6. **畫質差距不是必然**：現在的 v2 已經有 HDR 泛光、體積光、GPU 粒子；換引擎帶來的提升，主要在「工具效率」與「後處理品質」，不是所有地方都會立刻變好。

3. 硬體：RTX 2070 Super（8GB VRAM）、Intel i7-8700K、16GB RAM → 目標 1080p／60fps，不開硬體光追；Forward+ ＋ D3D12。

**已建立 `godot/`（Godot 4.6，Windows 預設 D3D12 + Forward+）驗證專案**
- 內容：11 艘艦艇 GLB（含鐵墓）、MultiMesh 艦隊（×1≈網頁版開場 149 艘，最高 ×64）、天空星雲著色器、光束著色器＋GPU 粒子電焊火花、泛光／體積霧／ACES 調色、有衰減的鐵墓紅光、自由飛行鏡頭、HUD（顯卡／FPS／艦數）、自動壓力測試（`-- --benchmark`）。
- 雲端驗證：Godot 4.6 無頭匯入、執行與自動測試無錯誤；用軟體 Vulkan（llvmpipe）實際渲染出畫面，艦艇／鐵墓／光束／星空都正常顯示（幀數在軟體渲染下無意義）。
- 尚未驗證：D3D12 實機畫質與幀數、電焊火花與光束的觀感 → 需要使用者在自己的電腦上跑（見 `godot/README.md`），把 `bench.csv` 與截圖貼回來，作為階段 1 的判斷關卡。

**引擎版本（2026-10-21）**：Godot 4.7 穩定版為基準；4.8 目前只有 beta（4.8-beta1），已驗證驗證專案在 4.6／4.7／4.8-beta1 都能匯入、執行、渲染（無需改動）。待 4.8 穩定後再升級；階段 2 起使用 .NET 版（C#）。

**階段 1 實測結果（使用者 PC：RTX 2070 SUPER／D3D12 `api=12_0`，2026-10-21）** — 原始資料 `godot/results/bench_rtx2070s_2026-10-21.csv`
| 艦隊 | 艦艇數 | FPS |
|---|---|---|
| ×8 | 1192 | 328 |
| ×16 | 2384 | 72~83（開 M 移動時） |
| ×32 | 4768 | 54 |
- 網頁版開場約 150~400 艘；Godot 在 2400 艘仍有 70+ fps、在 4768 艘仍有 54 fps，**效能關卡通過**（頻寬遠超需求，剩下的預算可以給光照、爆炸、煙霧、後處理）。
- 使用者回饋：×16 才開始有壓力。
- 畫面觀察：艦體偏白偏亮（網頁版貼圖為了無色調映射而提亮，進 ACES 後過曝）→ 需重新調光與材質曝光。
- 下一步（進行中）：Squadron 42 風格的爆炸原型（花椰菜火球＋煙＋火花＋碎片＋短命暖光源，見 `godot/scripts/explosion.gd`，按 X／C 觸發，Z 連續爆炸）與光照重調。

**爆炸原型第二版（2026-10-22，依使用者回饋）**
- 回饋：橘色適中；煙不夠黑、沒有體積感；火花要更多；爆炸光沒有照亮艦體；要加反物質軍團的**紫色焰**爆炸。
- 根因（爆炸光沒照亮艦體）：Godot 點光源是線性衰減，原本強度（約 100）在數百單位外幾乎無效；實測綠色測試光 300 才在 190 單位外開始明顯。改為強度 `size×14` 峰值（再衰減）、範圍 `size×7`，艦體靠近爆炸的一面現在會被染上暖色（紫色爆炸為紫色）。
- 煙：改用高度場假法線（團塊暗心亮邊）、近黑底色、只讓「朝向爆炸中心」的面被火光染色並隨距離／壽命衰減，加冷色主光；火花 140→320 顆×2 層，另加慢速餘燼層。
- 紫色焰（`Explosion.spawn(..., style=1)`）：紫色火球、粉紫火花、紫色煙光與紫色光源。鍵：X／C 橘色小／大，V／B 紫色小／大，Z 連續（40% 紫色）。
- 體積霧預設關閉（原設定影響不明顯）。

**爆炸原型第三版（2026-10-22，依使用者提供的 SQUAD 爆炸影片與自錄畫面）**
- 觀察（SQUAD）：①高亮度花椰菜火球 + 向外放射的黑煙束 → ②火球冷卻、外緣橘色、周圍長出很黑的濃煙 → ③**濃煙為主、火光為輔**：巨大暗灰黑積雲，內核火球只剩一圈橘色餘燼 → ④後期幾乎只剩灰黑煙塔與零星火星。自錄畫面的問題：煙被火光染成一片扁平橘色圓盤。
- 作法：火球縮短（壽命 1.1 秒）並後半縮小；煙 40 團、壽命 11 秒、持續膨脹、更黑、法線更凹凸；煙的火光時間軸改為前 30% 強、之後只剩微弱餘燼，只染朝向爆炸中心的面；冷色主光讓暗煙邊緣可辨。
- 遊戲規則：**紫色焰＝反物質軍團艦艇被擊毀**（V／B）；聯軍艦艇被擊毀＝橘色（X／C）；**聯軍飛彈命中反物質軍團艦艇＝先橘後紫**（N，style 2：火球、煙、火花、光色由橘漸變為紫）。連續模式（Z）依比例混合三種。

**爆炸原型第四版（2026-10-22）**：使用者回饋「火光完美、先橘後紫超棒、煙不夠黑且厚度不足」。原因：煙的透明度太低（半透明可見星星）、底色與冷光太亮、粒子未依深度排序。改為：底色近純黑、透明度拉高（團塊核心完全不透明、壽命前 60% 不淡出）、輪廓用噪聲侵蝕成凹凸積雲邊緣、粒子 60 團且 `DRAW_ORDER_VIEW_DEPTH` 排序、火光對煙的染色 ×0.55（避免紫色煙泛成淡紫）。

**爆炸原型第五版（2026-10-22）**：使用者回饋「煙夠黑但太厚、太久，大戰時處處爆炸會什麼都看不到，要快點褪去」。煙壽命 11→5.5 秒、約 1.6 秒後開始淡出、數量 60→42 團、尺寸 ×0.83、核心不透明度略降（×1.6、整體 ×0.9）；煙內火光時間軸同步縮短。粉紫星雲背景維持不動。

**爆炸原型第六版（2026-10-22）— 橘色／紫色／先橘後紫 各 5 種變體（共 15 種）**
- 變體：0 經典、1 連爆（接連 3 次小爆，位置與延遲亂數）、2 噴流（定向火舌，火花與煙順同一方向）、3 閃爆（強光、火花 700 顆、煙少而快散）、4 悶燒（火光較暗、煙與餘燼多、碎片多）。
- 亂數：每次爆炸隨機挑變體；尺寸 ×0.88~1.15；火球顏色（橘：偏黃偏紅；紫：偏藍偏洋紅）小幅亂數；噴流方向亂數。
- 呼叫：`Explosion.spawn(parent, pos, size, style, variant=-1)`；`-- --explode-gallery` 展示牆。

**爆炸原型第七版（2026-10-22）— 每種顏色增至 10 種變體（共 30 種）**
- 新增 5 種：5 環形衝擊（火球與火花排成向外擴張的環）、6 串燒（沿一條軸線 5 連爆）、7 花瓣（5 道細火舌放射）、8 延遲爆（先一小團悶光，0.4 秒後整個炸開）、9 碎片風暴（長曳光火花 620 顆＋碎片 230 片）。
- 展示牆 `-- --explode-gallery` 改為 3 列 × 10 欄。

**第八版（2026-10-22）— 刪除變體、爆炸效能保護、艦體損傷**
- 依使用者要求刪除「串燒」「碎片風暴」，每種顏色剩 8 種變體（共 24 種）。
- **爆炸效能保護**（`explosion.gd`）：①距離降級——離鏡頭越遠粒子越少（2500~9000 單位線性降到 12%）；②同時爆炸上限 14 顆，超過的新爆炸降成輕量版（火球＋少量火花，不放煙／餘燼／碎片／光源）；③動態光源上限 6 盞，只有近處爆炸配光源；④連爆的子爆炸不再連鎖，預算吃緊或遠處時取消。預算只計前 5 秒。
- **艦體損傷**（`shaders/ship_damage.gdshader`）：MultiMesh 的 custom data 每艘艦一個損傷度與種子；視差遮蔽貼圖（POM）裂縫＋燒蝕坑、焦黑、熔岩脈動光、螢幕空間法線擾動、艦燈閃爍、距離 LOD。Godot 無 Tessellation 著色器，故採 POM。
